# Beyond UI

**The one-stop skill for $50k-craft UI — websites, webapps, mobile, desktop.** The output should read
like work a design studio charged five figures for. That never comes from an agent inventing a gradient
hero from memory. It comes from four moves, in this order:

1. **ROUTE** the right skills — 5 permanent + 5 for this project, exactly 10, chosen deterministically.
2. **STUDY** what already wins — exactly 5 award-winning references, torn down to their design systems.
3. **IMPORT** what already exists — shadcn/ui for every control, the animated registries for motion and
   effects. Custom code is the last resort, not the first instinct.
4. **PROVE** it works — the app is exercised like a human, and the gate refuses unsupported claims.

## Three failure modes this skill exists to kill

1. **AI slop** — centered hero, three feature cards, Inter everywhere, purple-blue gradient, emoji icons,
   `transition-all duration-300` on everything, `rounded-2xl bg-white/10 backdrop-blur`.
2. **Reinventing the wheel** — hand-writing a marquee, a dialog or a text-effect that a registry ships,
   then shipping a broken version of it. This is the single biggest source of "broken AI UI".
3. **Unused tooling** — installing 33 skills and reading none. If a skill is routed, its rules bind the
   build and the run cites them; if it is not routed, it is not installed.

## The numbers are contracts, not suggestions

| Contract | Value | Enforced by |
|---|---|---|
| Permanent skills | **5** (star-ranked top design skills) | `assets/skills-catalog.json` → `selection` |
| Routed skills per project | **+5** (deterministic score of the project profile) | `scripts/skills-router.mjs select` |
| Total skills installed | **exactly 10 — never the whole catalogue** | `skills-router.mjs verify` · G3 |
| Reference sites | **exactly 5 — never 10** | G4 · `skills-router.mjs verify` |
| Base components | **shadcn/ui first**, animated registries second, custom last | `scripts/import-ledger.mjs audit` · G13 |
| Citations | ≥5, **plus one per routed skill** | G7 |
| QA journeys | ≥1, machine-generated | `scripts/qa.mjs journey` · G14 |

## Non-negotiables

0. **Route the skills before you work — no bypass.** Run `node scripts/bootstrap-upstream-skills.mjs`:
   it detects the project, selects the 5 routed skills, installs exactly the 10, and installs the tool
   layer. If a skill cannot be installed, fetch its raw `SKILL.md` URL, READ it, and record the miss in
   `.beyond-ui/state.json` → `skills.missing`. Never proceed as though a skill had been read.
1. **Follow the routed skills, and show it.** `.beyond-ui/SKILL.md` (generated) carries each skill's
   binding rules. Every load-bearing decision cites its source, and every routed skill is cited at
   least once (`skill://<id> -> <rule>`). G7 fails the run otherwise.
2. **Scout before you design.** No layout, palette, type scale or animation is chosen before
   `references/SCOUT.md` has been executed and `.beyond-ui/scout.md` written.
3. **IMPORT, don't reinvent.** shadcn/ui supplies every control (button, input, dialog, dropdown, table,
   form, toast, tab, sheet, tooltip, menu). The animated registries supply every motion/effect piece
   (`@magicui`, `@aceternity`, `@animate-ui`, React Bits, Animata, Motion Primitives — see
   `references/COMPONENTS.md`). Hand-rolling what a library ships is a **defect**, not a style choice.
   Custom code is allowed only for the genuinely bespoke 5%, and only with a recorded reason
   (`beyond-ui:custom <reason>` in-code or `state.components.handWritten`). G13 fails the run otherwise.
4. **The plan hands you real blocks.** `scripts/plan.mjs` scores `assets/block-catalog.json` against
   this project's evidence and emits `SECTION-PLAN.md` + `BLOCK-MAP.md` (embedded in the synthesis as
   §10): each section names its primary registry block **with the exact install command**. Build those
   blocks. Hand-writing a section the catalog covers is a defect unless scout.md records why.
5. **Motion is mandatory, but never decorative-only.** Every motion decision respects
   `prefers-reduced-motion`. One entrance grammar per page.
6. **No unverified UI claims.** A UI change is done when it was rendered and looked at — screenshots at
   3 viewports, plus the QA journey through the real app. G9 + G14 fail the run otherwise.
7. **No generic copy.** Placeholder lorem, "Empower your workflow", unnamed customer logos are defects.
8. **Preserve the project's identity.** An existing brand/design system wins over your taste.
9. **Install the tool layer — automatic, skip-if-present.** Playwright + chromium, `skillui`, `opensrc`,
   **Scrapling** (keyless acquisition — MCP tools preferred, CLI fallback), **browser-use** (human-like
   QA), the `playwright-skill`. Chromium is the only hard requirement.

## The operating loop

```
0a BOOTSTRAP  node scripts/scaffold-state.mjs             # .beyond-ui/state.json + scout.md scaffolding
             node scripts/bootstrap-upstream-skills.mjs   # routes + installs EXACTLY 10 skills, tool layer
             (POSIX shells: scripts/bootstrap-upstream-skills.sh)
0b ROUTE      node scripts/skills-router.mjs status         # confirm 5 permanent + 5 selected; digest exists
0c RECON      stack, brand, existing design system, motion budget, audience  (read the routed skills' rules)
1  SCOUT      galleries + prompt sources + registries, filtered to this product   -> .beyond-ui/scout.md
2  SELECT     score candidates -> EXACTLY 5 references        -> .beyond-ui/references-selection.json
3  TEARDOWN   node scripts/teardown.mjs run    # 5 x (skillui + playwright capture + scrapling) -> synth -> plan
4  DIGEST     node scripts/skills-router.mjs digest   # .beyond-ui/SKILL.md: the 10 skills' rules + the build sheet
5  DIRECTION  one binding contract (aesthetic, type, colour, spacing, motion) inside the plan's bounds
6  COMPOSE    node scripts/import-ledger.mjs plan    # the import list
             shadcn primitives -> registry blocks -> effects -> ONLY THEN custom (with a reason)
7  BUILD      token-driven, real copy, real states (loading/empty/error), responsive by construction
8  QA         node scripts/qa.mjs journey <url>      # use it like a human: click, type, scroll, keyboard
9  CRITIQUE   references/CRITIQUE.md against the RENDERED page; fix hard fails; re-render
10 VERIFY     screenshots 390/768/1440 + reduced-motion + keyboard + console + token audit
11 GATE       node scripts/import-ledger.mjs audit && node scripts/skills-router.mjs verify
             && node scripts/verify-run.mjs        # G1-G14 — exit 1 = the run is NOT done
```

Steps 1–5 are ~25–40% of the work and are the ones agents skip. Budget them. The output quality is
decided there, not in the CSS.

### 0a–0b. Bootstrap and route — mandatory

```bash
node scripts/bootstrap-upstream-skills.mjs          # --global for user scope, --check to report only
node skills-router.mjs status                        # what is routed and why
```

The router reads `assets/skills-catalog.json` (star-ranked, verified) and the detected project profile
(framework, Tailwind major, motion library, platform, concerns) and scores the pool:

- **5 permanent** — `frontend-design` (Anthropic, ★179k), `ui-ux-pro-max` (★132k),
  `frontend-ui-engineering` (★100k), `taste` (★91k), `impeccable` (★73k). Always installed, always bind.
- **+5 routed** — scored `2·surface + 2·stack + 3·concern`, ties by stars then id. A React+motion app
  routes `web-design-guidelines`, `react-view-transitions`, `hallmark`, `refactor-ui`, `bencium-design`;
  an RN build routes `react-native-skills`; a compliance-heavy build routes `accesslint`. Same project
  profile → same 10 skills, every time.

Re-running is idempotent. `node scripts/skills-router.mjs prune` removes beyond-ui-installed skills that
fell out of the active set (never touches skills you installed yourself).

**Reading is not claiming.** The digest (`.beyond-ui/SKILL.md`) extracts each skill's binding rules from
its real `SKILL.md`. When one of those rules changes a decision, write the citation
(`skill://<id> -> <rule>` + `appliedIn`). G7 fails a run where any routed skill went uncited.

### 1–4. Scout → select 5 → teardown 5 → digest

Execute `references/SCOUT.md`, then `references/TEARDOWN.md`:

```bash
node scripts/teardown.mjs init     # scaffold references-selection.json
# … fetch 2-4 galleries via the Scrapling MCP tools, score candidates, pick EXACTLY 5 …
node scripts/teardown.mjs run      # 5 x (skillui ultra + playwright capture + scrapling deep) -> synth -> plan
node scripts/skills-router.mjs digest   # condense the 10 routed skills + the plan into .beyond-ui/SKILL.md
```

Five references, condensed hard. Per site: **skillui** (tokens, keyframes, sections, interaction diffs),
**playwright capture** (computed truth: :root tokens, fonts, keyframes, hover/focus deltas, shots at
390/768/1440), **scrapling** (real copy structure, keyless). The synthesis carries real numbers —
extracted accents ranked by owner count, the type scale, spacing bases, the keyframe vocabulary, real
easings/durations, the section inventory in DOM order, and measured WCAG ratios — and embeds the
hand-picked build plan as §10.

The digest then makes the whole thing actionable in one file: **the 10 skills' binding rules by phase,
the direction contract, and the build sheet with exact install commands.** This is what you actually
build from.

### 5. Direction — the design contract

Write, in this order: **the Design Read** (one line — surface, audience, visual language) then the
contract: aesthetic name · type (display/body/mono + loading) · colour (OKLCH values, neutral ramp, one
accent, one signal) · spacing & rhythm · motion (easing set, durations, entrance strategy,
reduced-motion fallback) · references · non-goals · **evidence per field** (DESIGN-SKILL.md §n or
`teardown/<slug>`). It is binding for the rest of the build.

### 6–7. Compose and build — import-first, in this order

1. **shadcn/ui first.** `npx shadcn@latest add …` with the de-duplicated primitive list from
   `BLOCK-MAP.md` §1, restyled via tokens/CSS variables — never forked into a one-off.
2. **The planned registry blocks second.** `BLOCK-MAP.md` §2 gives one primary per section with its
   exact command. Stick to the 2–3 registries the plan names.
3. **3D/WebGL third** (only when the brief is 3D) — `references/THREEJS.md`.
4. **Effects fourth** — Anime.js v4, GSAP, Motion, Lenis, shaders, SVG — `references/EFFECTS.md`.
5. **Custom last**, with a reason, matching the imported code's standard.

`node scripts/import-ledger.mjs plan` turns the plan into a checklist; `audit` proves each block landed
as a real file that real source imports, and flags raw `<button>`/`<input>`/`<dialog>`/tooltip/toast
outside `components/ui`. Keep it green.

Build rules: Tailwind utilities bound to tokens (no magic hex in JSX) · real states (loading/empty/error/
partial/offline) · responsive by construction (design 390 → 768 → wide) · a11y throughout (landmarks,
one h1, labelled controls, visible focus, ≥4.5:1 in both themes, keyboard-complete).

### 8. QA — use it like a human

```bash
node scripts/qa.mjs journey <url>        # clicks the CTA, types into the form, scrolls, walks the keyboard
```

Machine-generated evidence: screenshots at 3 viewports, keyboard focus visibility, reduced-motion pass,
console cleanliness, a journey report in `.beyond-ui/qa/`. With **browser-use** registered
(`uvx browser-use --mcp`), drive the same flows conversationally and judge the feel; the Playwright
journey remains the reproducible gate. Fix what you find, then re-run.

### 9–11. Critique, verify, gate

`references/CRITIQUE.md` scores the **rendered** page (hard fails first, then the lowest gate). Verify:
render at 390/768/1440 · reduced motion · keyboard · console · perf smoke · token discipline · registry
integrity. Then:

```bash
node scripts/import-ledger.mjs audit      # G13 input: everything imported, nothing unmarked hand-rolled
node scripts/skills-router.mjs verify     # G3 input: 5+5 skills, 5 refs, every skill cited
node scripts/verify-run.mjs               # G1-G14; exit 1 = the run is not done
```

A failing gate is remedied by doing the missing work — never by relaxing the gate or editing
`state.json` by hand.

## Traps

- **Installing everything.** 33 skill folders installed and none read is the failure this router
  replaces. Install the 10; read the 10; cite the 10.
- **Ten references.** The condensed skill needs 5 handpicked references, not 10 scraped ones. G4 fails
  anything else — this is the "verify at last that it's 5 not 10" rule.
- **Reinventing components.** Before writing a component, search `assets/block-catalog.json` and
  `references/COMPONENTS.md`. If a registry ships it, import it. Your hand-rolled version will be
  worse: no focus trap, no reduced-motion, no RTL, no tests.
- **Registry roulette.** Installing eight animated components that do not share an aesthetic. The
  direction contract decides which 2–3 registries are in play (G10 caps it at 3).
- **Scout theatre.** Opening galleries, "getting inspired", writing the same generic hero. The scout
  file must name URLs and say what was taken from each.
- **Teardown theatre.** Running skillui on 5 sites, then building from the prior anyway. Every
  direction choice cites its contributing site (G7).
- **Version drift.** Tailwind v3 snippets in a v4 project; a `framer-motion` registry in a `motion`
  project. Check the stack first.
- **Motion everywhere.** Every element fading up on scroll is its own kind of slop.
- **Glassmorphism as a personality.** Blur + translucent borders + gradient blobs is one aesthetic.
- **Designing past the content.** A beautiful shell around placeholder text ships as a placeholder.
- **Ignoring the existing design system.** Extend it; do not fork a parallel one.
- **Accessibility as a final pass.** Retrofitted a11y is always worse and always more expensive.
- **Copying a reference wholesale.** Steal grammar — section order, density rhythm, motion behaviour —
  never identity, copy, imagery or assets.
- **Evidence fabrication.** Citations to files that do not exist, screenshots listed but not on disk:
  verify-run checks artifacts, not claims.
- **Plan as scripture.** Deleting a section the content cannot support is correct. Hand-writing a
  section the catalog covers is not — record why first.
- **QA as a screenshot.** A screenshot proves pixels, not behaviour. The journey (click, type, keyboard,
  reduced-motion, console) is the proof — G14 reads machine-generated reports, not your summary.
