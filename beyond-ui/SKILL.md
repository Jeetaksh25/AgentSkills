# Beyond UI

The goal is a UI that a working designer would sign their name to. That never comes from an agent
inventing a gradient hero from memory. It comes from **studying what already wins, stealing the
structure, and composing it from libraries that solved the hard parts first.**

Three failure modes this skill exists to kill:

1. **AI slop** — centered hero, three feature cards, Inter everywhere, purple-blue gradient, emoji
   icons, `transition-all duration-300` on everything, `rounded-2xl bg-white/10 backdrop-blur`.
2. **Skipping the scout** — writing CSS from scratch because it is faster than looking anything up.
   It is not faster. It is how the first failure mode happens.
3. **Invisible evidence** — running the skill, installing hallmark and impeccable, writing a scout
   file… then building from the model's prior and citing none of it. Every load-bearing decision
   must cite its source (`references/USAGE.md`), and `scripts/verify-run.mjs` fails the run without
   that proof.

## Non-negotiables

0. **Install the upstream skills before you work — no bypass.** Beyond UI is a composition layer over
   the design skills named in `references/SKILLS.md`. Run
   `node scripts/bootstrap-upstream-skills.mjs` first (or the manual `npx skills add …` equivalents it
   prints). If something cannot be installed, read its raw `SKILL.md` from the source URL and record
   the miss in `.beyond-ui/state.json` → `skills.missing`. Never proceed as though a skill had been
   read, and never paraphrase one from memory instead of fetching it.
1. **Scout before you design.** No layout, palette, type scale or animation is chosen before
   `references/SCOUT.md` has been executed and its findings written down. The scout result is an
   artefact (`.beyond-ui/scout.md`), not a vibe.
2. **Reuse beats invention, every time.** If a component, effect or animation exists in
   `references/LIBRARIES.md` or `references/COMPONENTS.md`, use it. Hand-rolled is the fallback for
   the 5% that is genuinely bespoke, and it must match the quality of what it stands in for. The same
   applies to 3D: a scene that needs WebGL is built with **Three.js / react-three-fiber** (or
   Threlte/TresJS, or `model-viewer` for a plain GLB) — via `references/THREEJS.md` — never with a
   hand-rolled canvas, a CSS fake, or a video pretending to be interactive 3D.
3. **The synthesis must hand you real blocks, not a direction.** `DESIGN-SKILL.md` is not allowed to
   be only tokens and judgement calls: `scripts/plan.mjs` scores `assets/block-catalog.json` against
   this project's own frame and teardown evidence, and the result — `SECTION-PLAN.md` (ordered build
   sheet) and `BLOCK-MAP.md` (element → exact registry install → restyle → states) — is embedded in
   the synthesis as §10. Build those blocks. Hand-writing a section that already exists in the catalog
   is a defect unless scout.md records why (licence, bundle, incompatibility, genuinely bespoke).
4. **shadcn/ui is the component base.** Every button, input, dialog, dropdown, table, form control,
   toast, tab, sheet, tooltip and menu comes from shadcn/ui unless a documented reason forbids it
   (see `references/SHADCN.md` → "When not to use shadcn"). Raw `<button>`, `<input>`, `<dialog>`
   and hand-built dropdowns are a defect, not a style choice.
5. **Motion is mandatory, but never decorative-only.** Scroll reveals, state transitions, and
   micro-interactions are expected. Animation that does not communicate hierarchy, causality or
   state is noise. Every motion decision respects `prefers-reduced-motion`.
6. **No unverified UI claims.** "Looks great" is not evidence. A UI change is done when it was
   rendered and looked at — screenshot at 3 viewports minimum (see § Verify).
7. **Do not ship generic copy.** Placeholder lorem, "Empower your workflow", "Supercharge your team"
   and unnamed customer logos are defects. Write real, specific, product-true copy or use the
   project's own domain language.
8. **Preserve the project's identity.** If the project has a brand, palette, type stack or design
   system, that wins over your taste. Beyond UI upgrades craft, not identity, unless a redesign was
   explicitly requested.
9. **Install the tool layer — automatic, skip-if-present.** The same bootstrap installs the
   capture/teardown tooling: playwright + chromium, `skillui`, `opensrc`, **Scrapling** (the keyless
   acquisition engine — stealth, Cloudflare solving, sessions and spiders; it replaces firecrawl *and*
   the LLM browser fallback, so nothing in this skill needs an API key or an account), and the GitHub
   agent skill `lackeyjb/playwright-skill`. Every step detects before installing; a globally-installed
   tool is never reinstalled. Chromium is the only hard requirement for the capture layer; Scrapling
   resolves itself from `scrapling` on PATH → `<python> -m scrapling.cli` → Docker and installs itself
   via pip when absent (`scrapling.autoInstall: false` in `.beyond-ui/config.json` disables that).
10. **Prove usage.** The run ends with `node scripts/verify-run.mjs` (G1–G12): artifacts, teardown
   evidence, DESIGN-SKILL.md completeness **including the embedded build plan**, plan traceability,
   rule citations, critique scores, verify screenshots. Exit 1 = the run is not done, and the report
   must say so.

## The workflow

```
0a BOOTSTRAP install the upstream design skills + the tool layer (both automatic, no bypass)
0b RECON     stack, brand, existing design system, motion budget, target audience
1 SCOUT      galleries + prompt sources + registries, filtered to this product's domain
1a SELECT    score candidates from verified galleries -> pick the best 10 for THIS project
1b TEARDOWN  skillui ultra + playwright capture + scrapling -> per-site design systems (10)
1c SYNTH     condense the 10 into ONE project skill -> .beyond-ui/DESIGN-SKILL.md
1d PLAN      score the block catalog against THIS frame -> SECTION-PLAN.md + BLOCK-MAP.md
             (embedded into DESIGN-SKILL.md §10 — real blocks, not a direction)
2 DIRECTION  pick ONE direction inside the plan's bounds (type, colour, spacing, motion)
3 COMPOSE    shadcn base -> animated registry components -> effects; only then custom code
4 BUILD      token-driven Tailwind, real copy, real states (loading/empty/error), responsive
5 CRITIQUE   run the anti-slop checklist against the rendered page, fix, re-render
6 VERIFY     screenshots at 3 viewports + reduced-motion pass + a11y pass + report
7 GATE       scripts/verify-run.mjs — citations + artifacts + scores, or the run is not done
```

Steps 1a–1d are the ones agents skip. They are the ones that decide whether the output looks
designed. Budget them: scout + select + teardown + synthesis + plan together are ~25–40% of the work,
not a formality.

### 0a. Bootstrap — mandatory, before anything else

The same bootstrap now also installs the **tool layer** (non-negotiable 9): `scripts/install-tools.mjs`
runs as its final stage — playwright + chromium (two separate checks), `skillui@1.3.4`, `opensrc`,
**scrapling** (resolved from PATH → `<python> -m scrapling.cli` → Docker, installed via pip when
absent, browsers fetched with `scrapling install --force`) and `lackeyjb/playwright-skill`. All
skip-if-present; a global install satisfies every check. Chromium is the only hard requirement for
the capture layer — without it, teardown is static-only and VERIFY is degraded, and the installer
exits 1 so that is loud rather than silent. Scrapling needs no key: the content layer therefore runs
on every machine, unlike the key-gated crawler it replaces.

```bash
node scripts/bootstrap-upstream-skills.mjs          # add --global for user scope, --check to report only
```

This installs the upstream design skills this skill composes — impeccable, hallmark, ui-ux-pro-max,
taste-skill, Anthropic `frontend-design`, Addy Osmani `frontend-ui-engineering`, the Vercel skills
(`web-design-guidelines`, `react-best-practices`, `composition-patterns`, `react-view-transitions`,
`react-native-skills`), bencium design, accesslint, the Refactoring-UI port and `skill-creator` — via
the official `npx skills` CLI, cloning anything that is not CLI native (and keeping it as reference
material when a repo ships no `SKILL.md`). `references/SKILLS.md` holds the full matrix, the manual
commands, the conflict rulings, and the proof required that they were actually followed.

`scripts/bootstrap-upstream-skills.sh` is the bash equivalent for POSIX shells.

Rules: run it once per project (re-running is idempotent); if a source cannot be installed, fetch its
raw `SKILL.md` URL and read it instead — a one-line `npx skills use <repo>@<skill> | claude` also works
for a single skill without installing; record `skills.installed` / `skills.missing` in
`.beyond-ui/state.json`. Proceeding without this step, or claiming compliance with a skill that was
never fetched, is a hard fail.

### 0b. Recon (≤ 10 tool calls)

Scaffold the run: `node scripts/scaffold-state.mjs` creates `.beyond-ui/state.json` (from
`assets/state-template.json`) and `.beyond-ui/scout.md`, without overwriting an existing run.

Then read the project before deciding anything: framework and version (Next/Vite/Astro/Svelte/RN),
Tailwind version, existing `components/ui` (is shadcn already installed?), tokens/theme file, font
loading, image pipeline, `package.json` animation deps, and the actual product domain. Check whether
shadcn is present before running `init` — re-initialising a customised system is destructive.

Everything the scout returns is filtered by the recorded stack: a Tailwind v3 snippet in a v4 project
is the most common copy-paste break, and a `framer-motion` registry in a `motion` project installs a
second, conflicting animation library.

### 1. Scout

Execute `references/SCOUT.md`. It defines the source universe (50+ inspiration galleries, 50+
prompt/template sources, 45+ component and animation libraries) and the protocol for using it:
pick the product's domain and aesthetic keyword set, pull 6–10 concrete references from the
galleries, pull 3–5 structural prompts from the prompt sources, then map every visual element you
intend to build to a library that already ships it.

Output `.beyond-ui/scout.md` with: `references:` (URL + what is stolen from it), `library map:`
(element → library → exact install/registry command), `rejected:` (what you saw and why it does not
fit). This file is the design's justification; a UI with an empty scout file is unfinished.


### 1a–1d. Select → Teardown → Synthesize → Plan — the deep-insight phase

Execute `references/TEARDOWN.md`. The scout looks at references from the outside; the teardown opens
them up and reads their design systems from the inside; the plan turns that evidence into a hand-picked
build sheet.

```bash
node scripts/teardown.mjs init     # scaffold .beyond-ui/references-selection.json
# … fill the frame + score candidates from the verified galleries (web AND mobile-app) …
node scripts/teardown.mjs run      # 10 × (skillui ultra + playwright capture + scrapling) -> synth -> plan
```

- **1a SELECT** — score every candidate from 2–4 verified galleries with the weighted rubric
  (domain ×3, page-type ×2, award ×2, recency ×1.5, aesthetic ×1.5, technique ×1, platform ×1) and
  pick the best **10** under the diversity constraints (≤2 per gallery, ≥3 awarded, ≥1 mobile-evidence).
  Mobile-app projects select from Mobbin / Page Flows / Refero instead of the web galleries.
  Fetch every gallery through `node scripts/scrapling.mjs scrape|map <url> <out>` — one bridge, no key,
  with automatic escalation `get → fetch → stealthy-fetch`, so the JS-only and 429 sources in
  `assets/config.json → galleries.jsOnly` are reachable.
- **1b TEARDOWN** — per site, three independent layers: **skillui** (ultra mode: tokens, keyframes,
  scroll journey, interaction diffs, DOM components), **playwright deep capture**
  (`scripts/capture-site.mjs`: :root tokens, loaded fonts, every keyframe, transitions in use,
  computed styles for body/h1/a/button/…, section inventory, motion-library detection, hover/focus
  diffs, screenshots at 390/768/1440), and **scrapling acquisition**
  (`scripts/scrapling.mjs deep`: `content.md` + top same-origin pages + `links.json` — the real copy
  structure). Keyless, so this layer runs everywhere instead of being silently skipped.
- **1c SYNTH** — `node scripts/teardown.mjs synth` condenses the 10 teardowns into ONE binding project
  skill: `.beyond-ui/DESIGN-SKILL.md`. It now carries **real numbers**, not adjectives: extracted accent
  and neutral values ranked by how many references used them, the actual type scale per heading, base
  spacing units, the keyframe vocabulary with owner counts, the transition durations/easings in use,
  the section inventory in DOM order, captured hover/focus deltas, and **WCAG ratios computed from the
  captured computed styles** (with the failing pairs named as "do not reproduce").
- **1d PLAN** — `scripts/plan.mjs` (run automatically by `synth`) scores `assets/block-catalog.json`
  against this project's frame and teardown evidence and emits `PLAN.json`, `SECTION-PLAN.md` and
  `BLOCK-MAP.md`, then embeds them as §10 of the synthesis. This is the "real blocks, not a direction"
  step: an ordered build sheet where each section names its **primary registry block with the exact
  install command**, its alternatives, its build rules, its content rules, its motion, its a11y duties
  and the hard fails to avoid — plus a single motion grammar with a concrete recipe, and the peer
  dependencies to check before installing anything.

The synthesis is **evidence, not a decision** — DIRECTION still chooses, but now it chooses from
extracted easing curves and spacing bases instead of vibes, and it chooses *inside* the plan's bounds:
deleting a planned section because the content cannot support it is correct; adding one the catalog
already covers is not. Cite the contributing site per choice. Plagiarism boundary unchanged: steal
grammar, never identity, copy, imagery or assets.

### 2. Direction — the design contract

Write two things, in this order.

**The Design Read** — one line, before any code: surface, audience, and the visual language you are
reading the brief as. *"Reading this as: B2B SaaS landing for technical buyers, with a Linear-style
minimalist language and one kinetic moment in the hero."* If the brief is ambiguous on something that
changes the design, ask exactly one question rather than guessing wide.

Then the contract:

- **Aesthetic name** — one phrase ("Swiss editorial with a warm paper substrate", "dense terminal
  brutalism", "soft neumorphic fintech"). Not "modern and clean".
- **Type** — display + body + mono faces, with the exact loading strategy. Banned as the only choice:
  the default system stack, Inter-by-reflex, and any face the project already uses *unless* it is
  genuinely the right answer. `references/DESIGN.md` lists the vetted type sources, and DESIGN-SKILL.md
  §2 gives the families the references actually load — choose from those two lists, not from memory.
- **Colour** — the actual values (OKLCH preferred), with the neutral ramp, one accent, one signal
  colour, and the surface/elevation strategy. No purple-on-dark-gradient default. DESIGN-SKILL.md §1
  ranks the candidate accents by how many references used them, and §7 gives measured WCAG ratios.
- **Spacing & rhythm** — the scale, the section rhythm, the max content width, the grid. DESIGN-SKILL.md
  §3 lists the base units observed across the references.
- **Motion** — the easing set, the durations, the entrance strategy, the scroll behaviour, and the
  reduced-motion fallback. Start from the grammar the plan picked (DESIGN-SKILL.md §10, motion block)
  and `references/MOTION.md`.
- **References** — the 3+ real sites this direction is derived from.
- **Non-goals** — what this design deliberately will not do.
- **Evidence** — each contract field cites its source: `DESIGN-SKILL.md §n` or `teardown/<slug>`
  for direction choices, `skill://<name> -> rule` for upstream rules. Citations go to
  `state.json -> ruleCitations` as they are decided (`references/USAGE.md`).

This contract is binding for the rest of the build. Deviating mid-build is how a page ends up with
five competing aesthetics.

### 3. Compose

Order is fixed, and it is the whole point of this skill. **The plan already made most of these
choices** — DESIGN-SKILL.md §10 names the primary block and the exact install command per section, so
compose means "install what §10 says, in §10's order":

1. **shadcn/ui first** — `npx shadcn@latest add …` with the primitive list from BLOCK-MAP.md §1 (it is
   de-duplicated across every planned section), then restyle via tokens/CSS variables, never by
   forking the component into a one-off.
2. **The planned registry blocks second** — BLOCK-MAP.md §2 gives one **primary** per section plus
   documented alternatives, with peers. Stick to the 2–3 registries the plan names; adding a fourth is
   registry roulette (`references/COMPONENTS.md` has the full catalogue when a primary is unavailable).
3. **3D / WebGL third, when the brief is 3D** — read `references/THREEJS.md` first: it decides whether
   3D is justified, picks the library (three.js → react-three-fiber + drei; Threlte/TresJS for
   Svelte/Vue; `model-viewer` for a plain GLB viewer), and gives the asset pipeline (`gltfjsx
   --transform`, Draco + KTX2), the scene patterns, and the performance/accessibility guards.
4. **Effects fourth** — Anime.js v4, GSAP (+ free plugins), Motion, Lenis, shaders, SVG animation,
   liquid glass; see `references/LIBRARIES.md` and `references/EFFECTS.md`.
5. **Custom last** — only what is genuinely bespoke, written to the same standard, reusing the
   project's tokens and the primitives' patterns (Radix behaviours: focus trap, aria wiring, escape).
   Then record what you composed in `state.json -> composedSections` and `state.json -> components`,
   because G12 checks the build traces back to the plan.

### 4. Build

- Tailwind utilities bound to tokens; no magic hex in JSX. Dark mode is a token swap, not a second
  stylesheet.
- Real states: loading (skeletons matching the real geometry), empty (with a real next action),
  error, partial, offline, permission-denied. A page with only the happy path is unfinished.
- Responsive by construction: design the 390px layout, then the 768px, then the wide one. Reflow
  intentionally — do not let the desktop layout shrink.
- Accessibility is not a polish step: semantic landmarks, one h1, labelled controls, visible focus,
  contrast ≥ 4.5:1 in both themes, keyboard-complete flows.

### 5. Critique

Run `references/CRITIQUE.md` against the **rendered** page, not the source. It is a scored
checklist with hard fails (the slop detectors) and quality gates (hierarchy, rhythm, restraint,
detail). Fix every hard fail, then the lowest-scoring gate, then re-render before scoring again.

### 6. Verify

A UI change is complete when all of these were observed:

| Check | Pass condition |
|---|---|
| Render | Screenshots at 390 / 768 / 1440 (and the project's real breakpoints) — visually inspected |
| Reduced motion | With `prefers-reduced-motion: reduce`, nothing critical disappears and no layout breaks |
| Keyboard | Full interactive flow reachable and operable by keyboard, focus visible throughout |
| Console | No errors/warnings from the new code; no hydration mismatches |
| Perf smoke | No new long tasks on load; hero animation does not regress LCP; no CLS from late-loading fonts/images |
| 3D (when present) | Poster is the LCP element; scene paused off-screen; frozen under reduced motion; asset bytes and throttled FPS recorded (`references/THREEJS.md`) |
| Token discipline | No raw hex/`px` outside tokens; dark mode verified |
| Registry integrity | Every added registry component still updates/compiles; unused ones removed |

Record the artefact paths in `.beyond-ui/state.json`, then emit the pre-emit critique stamp and report
in ≤ 8 lines: Design Read, direction chosen, files touched, libraries used, checks run with results,
and anything deliberately deferred. An axis below 3 in the stamp means a revision pass is still owed —
the work is not done.

### 7. Gate — the run is not done until verify-run passes

```bash
node scripts/verify-run.mjs            # G1–G12; exit 1 = incomplete
```

Gates: G1 state · G2 scout evidence (4+ URLs, library map) · G3 skills installed-or-documented ·
G4 selection quality (6+ refs, 3+ awarded) · G5 teardown artifacts (6+ sites with evidence) ·
G6 DESIGN-SKILL.md complete (12 sections, including the embedded build plan) ·
G7 rule citations (≥5, each {decision, source, appliedIn}) ·
G8 critique recorded (12 gates, none <3, mean ≥4.0) · G9 verify evidence (3+ screenshots,
reduced-motion + keyboard + console) · G10 the plan is concrete (archetype + motion grammar + 4+
hand-picked sections, each with build rules and a block) · G11 the plan is embedded in DESIGN-SKILL.md
(build sheet + real `npx shadcn@latest add @ns/item` commands) · G12 the build traces back to the plan
(`state.components` / `state.composedSections`). A failing gate is remedied by doing the missing work —
never by relaxing the gate or editing state.json by hand. Full contract: `references/USAGE.md`.

## Traps

- **Scout theatre.** Opening three galleries, "getting inspired", and writing the same generic hero.
  The scout file must name URLs and say what was taken from each.
- **Skipping the bootstrap.** Writing a landing page from memory while the upstream skills sit
  uninstalled. If `skills.missing` is non-empty, read the raw `SKILL.md` files before building.
- **Registry roulette.** Installing eight animated components that do not share an aesthetic. The
  direction contract decides which two or three registries are in play.
- **Version drift.** Copying a Tailwind v3 / `framer-motion` snippet into a v4 / `motion` project.
  Check the stack first; adapt or skip.
- **Motion everywhere.** Every element fading up on scroll is its own kind of slop. Motion earns its
  place by signalling hierarchy, cause, or state change.
- **Glassmorphism as a personality.** Blur + translucent borders + gradient blobs is one aesthetic,
  not a default — and it needs the `@supports` fallback plus a contrast check.
- **Designing past the content.** A beautiful shell around placeholder text ships as a placeholder.
- **Ignoring the existing design system.** A parallel set of tokens and components duplicates the
  project's and breaks it. Extend, do not fork.
- **Accessibility as a final pass.** Retrofitted a11y is always worse and always more expensive.
- **Copying a reference wholesale.** Steal grammar (section order, density rhythm, motion behaviour),
  never a full site's identity, copy, imagery or assets.

- **Teardown theatre.** Running skillui on 10 sites, then building from the prior anyway. DESIGN-SKILL.md
  §8 names the judgements still owed; every direction choice cites its contributing site (G7).
- **Copy-paste synthesis.** DESIGN-SKILL.md is evidence, not a decision — an award site's gradient-text
  headline is a data point, not permission to override the gradient-text ban.
- **Evidence fabrication.** A citation to a teardown file that does not exist, or screenshots listed but
  not on disk, is a hard fail — verify-run checks artifacts, not just claims.
- **Plan theatre.** Letting §10 be generated and then building something else. G12 traces the composed
  sections back to the plan; a section that exists in `assets/block-catalog.json` and was hand-written
  anyway needs its reason in scout.md.
- **Plan as scripture.** The opposite failure: shipping a section because the plan listed it, when the
  content cannot support it. The plan proposes; the content decides; delete freely and say why.
- **Content-layer theatre.** Claiming a site "has no motion" when `capture.json` returned no keyframes.
  No keyframes means CSS-in-JS or cross-origin, and the report must say exactly that.
